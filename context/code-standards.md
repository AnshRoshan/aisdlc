# Code Standards

## Language and types

- ESM JavaScript only; no TypeScript, no build step for the CLI.
- Two-space indentation. Descriptive names; no abbreviations except established domain terms (`SoD`, `EARS`).
- Comments explain why, never what. A comment that restates the line is deleted.
- Node >=18 for the CLI. Do not use APIs newer than the `engines` field without a fallback.

## Structure

- `engine.js` stays pure: parsed input in, verdict out. No filesystem, process, network or clock.
- `cli.js` owns effects: parsing argv, reading/writing files, spawning commands, exiting.
- `fsx.js` owns path and platform behavior. All argv passed to a process is an array; never a concatenated shell string.
- Harness layouts live in `harnesses.js`; seeds live in `templates.js`. A new artifact shape is a template change plus a test, not ad hoc string building.
- Canonical skills live in `skills/`. `packages/cli/skills/` is generated by `sync-skills.mjs` and never edited.

## Error handling

- Fail loud. A malformed artifact is an error with the file and the line, not an empty state.
- Every catch either fixes, retries, or rethrows with context. No empty catches.
- User-facing failures print the exact remedy, not a lecture.
- Exit codes are part of the contract: non-zero for a failed check, a stale approval, corrupt evidence or an invalid command.

## Testing

- `node --test`; tests live beside the code in `packages/cli/test/`.
- Every gate rule gets a test named after the failure it prevents.
- Fixtures use temporary directories. Tests never touch the real repo or the network.
- A bug fix ships a test that fails without the fix.
- Windows behavior (junctions, shims, drive letters) is tested, not assumed.
- Full suite: `npm --prefix packages/cli test`. Corpus: `node packages/cli/scripts/check-skills.mjs`.

## Security

- Never write secrets to artifacts, logs or evidence. Redact recognized credential output.
- The CLI refuses credential flags in recorded commands.
- Skills are untrusted input at install time; the corpus checker rejects undeclared files and broken claims.
- Optional signing uses external binaries; the core must remain verifiable by hashes alone and honest about what that proves.

## Quality gates

Before a unit is complete:

- tests pass;
- corpus check passes;
- site builds;
- `claude plugin validate .` passes;
- the spec's smoke path has been run and its output recorded;
- no new runtime dependency without a decision record in `context/decisions.md`.

## Documentation

- A documented command is a test: it must exist in `cli.js`.
- A claim about enforcement must name the check that enforces it.
- Changelog entries are written from the actual diff, not from memory.
- Skill prose respects the budgets in `docs/conventions.md`; a warning means prune, not raise the ceiling.
